- **What I kept, and why:**
  - **Baseline-before-anything (`git init` + commit notebooks *with outputs*)** — given finding (3) this was non-negotiable, and it pays off twice: the stored outputs became the golden record, and `git diff` on an `.ipynb` now shows exactly which printed numbers move after each phase.
  - **Scraping golden metrics from already-executed notebook JSON** — this is the move that breaks the circularity of needing golden values *from* the notebooks being refactored. Zero notebook executions; my later manual re-run only has to *confirm* the pin.
  - **Content fingerprints instead of file hashes** — parquet writes aren't byte-deterministic, so a file hash would false-alarm on an identical rebuild. Row count + schema + `hash_pandas_object` sum + grand totals is the right invariant.
  - **`shares_k` named for its target, not a generic `default_k`** — the subagent's catch, and correct: k=7 is the *result* of 06's shares sweep, the level independently sweeps to k=6, and the Human branch sweeps a different grid. A generic name would have erased the finding that k was tuned per target.
  - **Killing the `Branch` base class and the `Scorer` hierarchy from the agent's original proposal** — the branches don't share a control flow (07's finding *is* the metric disagreement plus six diagnostic cells; 09 does a correlation study that isn't a prediction), so an inherited `ablation_ladder` would need so many hooks it would hide the very sequence the course grades. Protocol + free functions gets ~90% of the dedup with ~40% of the abstraction.
  - **Keeping 04's validation cell in the notebook while *also* porting it to pytest** — deliberate duplication: the PASS/FAIL roster is graded evidence for a human reader, the test file is the agent-runnable gate. They must agree.
  - **Pinning `n_cells` exactly while metrics use `approx` at 4 decimals** — a silently-changed scorable-cell population is the likeliest way a refactor corrupts a result, and it shows up in the count before the metric. It's the canary.
  - **Verification by side-by-side simulation rather than trust** — for each of 05–09 the agent ran the original and refactored logic against the real parquet in one process and compared. All frames bit-identical; every golden value reproduced, including 06's gradient-boosted rungs (floor TVD 0.2676/0.2659, learned 0.3141/0.2894, `best_level` k=6), the full k-sweep, `XCOLS` order, and all `n_cells` (5399/3941, 3850, 2727/2708, 3954/3949).
  - **Mutation-testing the new suite** — a green suite that can't fail is worthless. It detects a single 0.01-acre change, one dropped row, and a tampered per-cell value; and it quantified the dedup-don't-sum trap at exactly 12× (397.5M vs the correct 33.1M), which is now guarded.
